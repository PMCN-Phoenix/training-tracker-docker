## 1. 目标与范围

**目标**：给健身项目新增「训练感悟系统」—— 既能像练枪那样记录、分类、追溯训练感悟，又能把感悟**精确挂到具体动作的某一组**上，形成「点击动作 → 看历史组数 × 重量 → 侧栏对应每一组的当时感悟」的完整闭环；同时把 **PR 成绩体系**（总览 / 曲线 / 历史联动）和 **Grafana 数据跳转**纳入同一界面。

**做什么**：

1. 感悟数据模型（组级 / 动作级 / 训练日级三级粒度）落地 InfluxDB
2. Node-RED 消息解析扩展（训练消息里直接带感悟，或独立感悟消息）
3. 新增轻量前端页面：**增强三栏**（动作导航 → 训练详情 → 侧栏感悟）+ **双模式**（按动作 / 按日）+ **PR 体系**（总览 / 抽屉 / 多系列曲线）+ **Grafana 跳转**
4. 按日 Markdown 同步（人类可读、双向）
5. 简单统计（总数 / 今日 / 连续天数 / 覆盖动作数）

**不做什么**（本次范围外，后续再说）：

- 不做主题分类枚举（用自由 tags）
- 不做 HRV 等恢复数据接入（晨脉/意象只做展示，不做分析）
- 不动现有训练数据模型（ppl_\* 各 measurement 原样保留）
- 不做移动端 App（先 Web 页面 + 消息录入，页面响应式）

## 2. 产品形态（交互定义）

### 2.1 布局总览（增强三栏 + 顶栏）

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏 品牌 | 统计(总数/今日/连续/覆盖) | 按动作/按日切换 | PR总览 | 打开看板 │
├────────┬───────────────────────────┬───────────────────────┤
│ 左栏    │ 中栏                       │ 右栏                   │
│ 推/拉/蹲│ 动作标题 + 重量趋势迷你图    │ 侧栏感悟（与选中一一    │
│ 动作列表│ + PR卡片(可展开)            │ 对应）+ 筛选(方向/标签/ │
│ 感悟计数│ + 「在Grafana查看→」       │ 日期)                  │
│ PR红标  │ 历史训练轮（日期分组）       │ 组级/动作级/日级/待匹配 │
│ (最近测)│ 组行: 组号│重量│次数│徽标   │ 编辑/删除/补录         │
│        │ 空态引导                    │                       │
├────────┴───────────────────────────┴───────────────────────┤
│ 底部 数据说明条                                               │
└────────────────────────────────────────────────────────────┘
```

### 2.2 双模式（顶栏切换）

| 模式 | 左栏 | 中栏 | 右栏 |
|---|---|---|---|
| **按动作**（默认） | 动作导航（推/拉/蹲，15 动作） | 该动作全部历史：迷你图 + PR 卡片 + 训练轮 + 动作级感悟条 + 待匹配 | 与选中组/动作一一对应的感悟 |
| **按日** | 折叠为**当月迷你日历**（训练日蓝点、感悟日金点、都有双色、今天蓝框） | 中栏全宽：当天全部动作按推/拉/蹲分组列组行 | 默认当天日级感悟；点任意组看组级 |

- 按日模式点某天 → 中栏当天全貌 + 右栏当天感悟；无记录日期点击 → 空态引导
- 迷你日历可翻月，日历即导航

### 2.3 左栏（动作导航）

- 推 / 拉 / 蹲三组，15 动作；每个动作右侧感悟计数（金点 + 数字）
- **PR 红标**：仅当该动作存在"最近一次 PR 测试记录"时标细红点（语义 = PR 状态新鲜，非时间阈值；用户常测 PR，红标锚定最近一次结果）
- **红标 hover 浮层** = 该动作完整 PR 阶梯列表（每重量一行：35kg → 18 次），最高档高亮，底部「查看详情 →」进 PR 抽屉

### 2.4 中栏（按动作模式）

1. **动作标题行**：动作名 + 方向徽章 + 「在 Grafana 查看 →」（深链到该动作面板）
2. **重量趋势迷你图**（SVG，双线同轴）：
   - 实线 = 训练轮第一组重量（进步主线）
   - 虚线红 = PR 测试轮极限值（不参与实线）
   - hover 显示日期 + 重量；空数据动作显示"暂无训练记录"
3. **PR 卡片**（可展开收起）：
   - 一行一档 `重量 → 次数`（如 35kg → 18 次），**当前最佳档高亮** = 最近一次测试的最高档
   - 右下角「查看历史 PR →」→ 打开 PR 抽屉
4. **历史训练轮**：按日期倒序分组；每轮头部 = 日期 + 方向 + PR 测试红标（如有）+ 组数；组行 = `第N组 | weight | × reps | 💬徽标(数量)`
5. **动作级感悟条**（中金）、**待匹配卡片**（虚线橙）、**空态引导** 保留

### 2.5 右栏（侧栏感悟）

- 与中栏选中项**严格一一对应**：组级 / 动作级 / 日级 / 待匹配 四视图
- **筛选**：右栏顶部 方向(推/拉/蹲) + 标签 + 日期 三个轻量过滤
- 感悟卡：日期时间 + 来源 + 内容 + 标签 + 编辑 / 删除
- 底部「补录感悟」入口；**日级新建入口 = 顶栏日级随笔条右侧「+ 写当日随笔」按钮**（弹窗动作留空 = 日级）
- **日级视图整合**：当天全貌 = 日级感悟 + **当天晨脉值** + **意象打卡**（数据源 ppl_morning_hr / ppl_imagery，只展示不分析）

### 2.6 PR 体系（全屏总览 + 抽屉 + 曲线 + 联动）

**双入口 × 双粒度**：

| 功能 | 全局入口（顶栏「PR 总览」） | 局部入口（动作级） |
|---|---|---|
| PR 总览 | **全屏切换视图**：15 动作成绩单，每动作卡片 = 当前最佳档 + 全阶梯 + 历史 PR 入口 | 中栏 PR 卡片右下角 / 左栏红标浮层 → **右侧抽屉**（只看当前动作） |

- 全屏总览与抽屉**复用同一套组件**（一套抽屉两处入口，行为一致）
- **PR 曲线（多系列对比图，抽屉内顶部）**：
  - 每次 PR 测试 = 一条曲线（颜色 = 测试，按日期升序自动编号：第 1 次 = 最早；hover 显示日期）
  - **对比控件**：默认「全部对比」；切「两两对比」→ 两个下拉选"第 N 次 vs 第 M 次"，只画两条
  - 曲线连点规则：测了哪些档就连哪些点，未测档留缺口不强行连线
  - **训练档标记**：当前处方重量（如 47.5kg）用 ▼ 绿色虚线标在横轴对应位置
  - 数据点 hover 浮动显示「第N次（日期）· 重量 · 次数」
- **阶梯列表**：曲线下方折叠明细（点档位 → 联动）
- **历史 PR 联动**：历史 PR 轮按日期倒序；点**具体档位**（如 60×3）→ 抽屉关闭 → 中栏切回按动作模式 → 滚动高亮到对应组行 → 右栏显示该组感悟；全屏总览的历史 PR 入口用同一联动逻辑

### 2.7 视觉规范（深色精致版）

| 项 | 设计 |
|---|---|
| 背景 | 炭黑 `#0d1117` 打底，面板 `#151c26`，浮层 `#1a2230`，层级靠亮度不靠投影 |
| 主色 | 琥珀金 `#e8a23d`（品牌/感悟/PR 高亮），选中蓝 `#58a6ff`，达标绿 `#3fb950`，PR 红 `#f85149` |
| 数字 | 等宽字体（重量/次数/日期严格对齐，表格感） |
| 圆角/边框 | 卡片 10-12px、1px 细边框 `#232e3d`，hover 微亮 + 150ms 过渡 |
| 感悟层级 | 组级亮金 `#f0b429` / 动作级中金 `#c9a24b` / 日级柔金 `#8f7a3d`（同一金色系三档明度） |
| 徽标 | PR 红标、感悟 💬 金标、待匹配虚线卡、训练档 ▼ 绿虚线 |

## 3. 数据模型设计

### 3.1 现有训练数据（不动，只读）

现状（来自 flows.json parse-training，15 动作）：

- 每组一条点：measurement=`ppl_push_bench_flat` 等（每动作一个），tags=`direction`(push/pull/squat)、`exercise`(中文名)、`set_index`(从 1 起)、`session_id`(=`'s'+消息时间戳`)、`source`；fields=`weight_kg`, `reps`
- PR 测试：measurement=`ppl_pr_test`，tags 含 `type='pr'`，fields=`weight_kg`, `max_reps`
- 其他：`ppl_duration_min`（训练时长）、`ppl_morning_hr`（晨脉）、`ppl_imagery`（意象打卡）

**关键事实**：`session_id` 由「一条消息」生成 —— 同一训练轮发多条消息会产生多个 session_id。因此感悟与组的绑定**不能依赖 session_id 跨消息匹配**，统一用「date + exercise + set_index」三键锚定（见 §4.3）。

**PR 数据源**：PR 曲线 / 总览 / 红标全部读 `ppl_pr_test`；「每次测试」= 同一天（或同一次 PR 消息）的一组记录，按日期升序编号。⚠️ 待核查：用户更早"更新 PR"那批全动作全重量档数据是否已入库（见 §10）。

### 3.2 新增 Measurement：`ppl_reflection`

**Tags**：

| tag | 取值 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `ref_{YYYYMMDD}_{8位短uuid}` | ✅ | 唯一标识（复用练枪规则） |
| `date` | `YYYY-MM-DD` | ✅ | 感悟日期（默认消息当日，可显式指定） |
| `direction` | push / pull / squat / other | 组级 / 动作级 ✅ | 冗余便于筛选，由动作映射 |
| `exercise` | 动作中文名（如 平板卧推） | 组级 / 动作级 ✅ | 日级感悟缺省 |
| `set_index` | `1..N` | 仅组级 | 组级 = 具体第几组；动作级不填；日级不填 |
| `session_id` | 同消息训练数据的 session | 可选 | 若消息同时带训练数据则顺带记录，便于直接 join |
| `source` | phone / web | ✅ | 录入通道 |

**Fields**：

| field | 类型 | 说明 |
| --- | --- | --- |
| `content` | string | 感悟正文（一句话为主，Markdown 兼容） |
| `title` | string | 可选标题（页面编辑时可填，消息录入默认空） |
| `tags` | string | 自由标签，逗号分隔（替代练枪的主题枚举） |

**Line Protocol 示例**：

```
ppl_reflection,id=ref_20261011_3f9a2b1c,date=2026-10-11,direction=push,exercise=平板卧推,set_index=2,source=phone content="肩胛锁死后推起来更稳，下放节奏慢一点",tags="" 1730000000000000000
```

### 3.3 三级粒度语义

| 粒度 | exercise | set_index | 典型场景 |
| --- | --- | --- | --- |
| 组级（主） | 平板卧推 | 2 | 「平板卧推 第 2 组 感悟：……」（练完一组马上记） |
| 动作级 | 平板卧推 | 不填 | 「平板卧推 感悟：今天上胸感觉好」（动作练完后总结） |
| 训练日级 | 不填 | 不填 | 「推日 感悟：整体状态一般，组间拉长到 3 分钟」 |

展示端规则：组级感悟精确挂到组；动作级感悟显示在该动作卡片顶部；日级感悟显示在页面顶部（该日全局）及按日模式右栏。

## 4. 录入设计（Node-RED 扩展）

### 4.1 消息语法

在**现有 parse-training 之外**新增「感悟解析」逻辑（同一条消息可同时含训练数据 + 感悟，也可纯感悟消息）：

| 语法 | 绑定 |
| --- | --- |
| `平板卧推 第2组 感悟：肩胛锁死更稳` | 组级（date = 当日，exercise = 平板卧推，set_index=2） |
| `平板卧推 感悟：今天上胸感觉好` | 动作级（set_index 不填） |
| `推日 感悟：整体状态一般` / `感悟：今天状态差` | 训练日级（日级不指定动作时，可用方向词或省略） |
| `平板卧推 47.5kg×8 第1组 感悟：这组最顺` | 训练数据 + 感悟同发，顺带绑 session_id |

**识别词**：`感悟` / `心得` / `笔记` / `reflection`。触发后：

- 提取动作（复用现有 15 动作别名表 findExAt）
- 提取组号（`第(\d+)组`）
- 其余文本为 content，写入 `ppl_reflection`

**响应**：纯感悟消息返回 `已记录 1 条感悟（平板卧推·第2组）`；混录返回汇总。

### 4.2 前端页面补录 / 编辑 / 删除

页面右栏 + 弹窗提供：新建（选动作 / 组号 / 日期 / 内容 / tags）、编辑、删除（InfluxDB Delete API，练枪已验证的 delete 模式）。日级新建：顶栏「+ 写当日随笔」按钮（动作留空 = 日级）。

### 4.3 组级绑定的现实处理（宽松绑定）

练枪的 session_id 语义是「一次消息」，训练内多条消息 session 不同；且用户可能在录训练数据**之前**就先记了感悟。因此：

- **锚定键 = date + exercise + set_index**，不依赖 session_id 跨消息匹配
- 展示时 join 训练数据：按 date+exercise 取当天该动作记录的第 N 组（weight×reps 显示在感悟旁）
- 若当天该组记录尚不存在 → 页面显示「未匹配到组（待训练数据补录后自动匹配）」；训练数据补录后自然对上
- 同一天同一动作多个训练轮（如早 / 晚各练一次）：按记录时间就近匹配 —— **v1.0 只做自动匹配，手动改绑暂缓**（实际出现错配再加）

## 5. 展示载体：新增轻量前端（架构）

### 5.1 为什么不能只靠 Grafana

Grafana 只能做面板、跳转、drilldown，做不了「点击动作 → 右侧展开详情 → 侧栏逐组批注」的联动交互。健身项目目前无前端、无后端服务（只有 Node-RED / InfluxDB / Grafana）。

### 5.2 技术方案（克隆练枪 web 工程骨架，宿主进程跑，不进 docker-compose）

比对练枪实际部署后确认：练枪的 web（FastAPI + React）**不在 docker-compose 里**（compose 只有 influxdb/grafana/nodered 三个容器），而是宿主进程直接跑：`start.bat` 起 uvicorn + vite dev；`start-prod.bat` 先 `npm run build`，再由 FastAPI 用 StaticFiles + SPA fallback 托管 `frontend/dist`，生产单端口访问。健身版完全跟随这一形态。

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 编排 | 克隆练枪 `web/` 目录到 training-tracker-docker，宿主进程跑 | docker-compose **不加服务**；新增 `start.bat`（dev）/ `start-prod.bat`（prod） |
| 后端 | FastAPI（练枪同款，复制 app/{models,repositories,services} 骨架） | 感悟 CRUD + 训练历史查询 + 统计 + PR 查询；InfluxDB token 只留后端；`influx_client.py` 只改 4 个连接常量 |
| 前端 | React + Antd（练枪同款，复制 package.json 与 src 页面组件） | 增强三栏页面 + 弹窗表单 + SVG 图表；vite dev `5174`；生产由 FastAPI 托管 dist |
| 端口 | 后端 `8001` / 前端 dev `5174` / 生产单端口 `8001` | 避开 3000 / 1880 / 8086 / 练枪 8000、5173 |

**Grafana 跳转映射**：动作 → panelId 映射表（从 grafana/provisioning/dashboards/ppl-training.json 提取）；总看板 URL 固定；深链格式 `http://127.0.0.1:3000/d/ppl-training-monitor/<uid>?viewPanel=<panelId>&orgId=1`。

**备选（不推荐）**：无后端直连 InfluxDB（CORS + token 暴露，不安全）；Node-RED HTTP 当 API（查询/编辑体验差）。

### 5.3 后端 API 清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/reflections?date=&exercise=&direction=&set_index=&tag=&limit=&offset=` | 感悟列表（筛选） |
| POST | `/api/reflections` | 新建感悟 |
| GET | `/api/reflections/{id}` | 单条详情 |
| PUT | `/api/reflections/{id}` | 更新（删除 + 重写，保留 id） |
| DELETE | `/api/reflections/{id}` | 删除 |
| GET | `/api/training/exercise/{exercise}` | 该动作历史训练（按 session 分组：date/direction/session_id + 每组 weight×reps）—— 中栏数据源 |
| GET | `/api/reflections/stats` | 统计（总数 / 今日 / 连续天数 / 覆盖动作数） |
| GET | `/api/pr/tests` | 全部动作 PR 测试列表（按动作 + 日期分组，供 PR 总览 / 曲线 / 红标） |
| GET | `/api/day/{date}` | 某天全貌（当天全部训练组行 + 日级感悟 + 晨脉 + 意象）—— 按日模式数据源 |

### 5.4 前端页面结构（对照 §2）

- 左栏：动作列表（推 / 拉 / 蹲分组）或 迷你日历（按日模式）
- 中栏：按动作模式 = `/api/training/exercise/{exercise}` + `/api/reflections?exercise=` + `/api/pr/tests` 合并渲染；按日模式 = `/api/day/{date}`
- 右栏：选中组 / 动作 / 日 → 对应感悟 + 筛选
- PR 抽屉 + 全屏总览：`/api/pr/tests` 数据，SVG 多系列曲线
- 弹窗：新建 / 编辑表单
- 列表标记：有感悟的组显示 💬；PR 轮红标

## 6. Markdown 同步（保留练枪模式）

- 目录：`docs/记录/训练感悟/YYYY-MM-DD.md`（练枪为 游戏感悟，健身独立目录）
- 单条格式（组级示例）：

```
### 平板卧推 · 第2组（47.5kg×8）—— 肩胛锁死后推起来更稳
```
