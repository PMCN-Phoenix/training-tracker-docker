## 1. 目标与范围

**目标**：给健身项目新增「训练感悟系统」—— 既能像练枪那样记录、分类、追溯训练感悟，又能把感悟**精确挂到具体动作的某一组**上，形成「点击动作 → 看历史组数 × 重量 → 侧栏对应每一组的当时感悟」的完整闭环。

**做什么**：



1. 感悟数据模型（组级 / 动作级 / 训练日级三级粒度）落地 InfluxDB

2. Node-RED 消息解析扩展（训练消息里直接带感悟，或独立感悟消息）

3. 新增轻量前端页面：动作列表 → 训练详情（组 × 重量）→ 侧栏组级感悟

4. 按日 Markdown 同步（人类可读、双向）

5. 简单统计（总数 / 今日 / 连续天数 / 覆盖动作数）

**不做什么**（本次范围外，后续再说）：



* 不做主题分类枚举（练枪有 7 类主题，健身版先不分类，用自由 tags）

* 不做 HRV 等恢复数据接入

* 不动现有训练数据模型（ppl\_\* 各 measurement 原样保留）

* 不做移动端 App（先 Web 页面 + 消息录入）

## 2. 产品形态（交互定义）

用户原话形态：「在一个动作中点击它可以展示出来具体日期做的这个动作的组数 × 重量，在侧面可以一一对应在做某一组时候出现当时感悟」。

**页面布局（单页三段式）**：



| 区域 | 内容                                                               | 交互                                |
| -- | ---------------------------------------------------------------- | --------------------------------- |
| 左栏 | 动作列表（15 动作，按 推 / 拉 / 蹲 分组）                                       | 点击动作 → 中栏切换                       |
| 中栏 | 该动作历史训练：按训练轮（session）倒序，每轮一张卡片（日期 + 方向），轮内每行 = `第N组 weight×reps` | 点击某一行（某组）→ 右栏显示该组感悟；有感悟的行显示 💬 标记 |
| 右栏 | 侧栏批注：当前选中组的感悟（内容 + tags + 录入时间）；可编辑 / 删除；底部「补录感悟」入口              | 一一对应，选中哪组显示哪组                     |

**页面顶部统计条**：总感悟数 / 今日 / 连续天数 / 覆盖动作数。

**交互示意**（草案，实现前用可点击原型确认）：



```
┌─────────┬──────────────────────────┬───────────────────┐
│ 推日动作 │ 平板卧推 · 历史           │ 第2组 · 感悟       │
│ 平板卧推▶│ 2026-10-11 · 推日        │ 肩胛锁死后推起来更 │
│ 上斜卧推 │  47.5kg×8  第1组  💬     │ 稳，下放节奏慢一点 │
│ 窄距卧推 │  47.5kg×9  第2组  💬 ←─→ │ 2026-10-11 消息录入│
│ 站姿推举 │  47.5kg×8  第3组  💬     │ [编辑] [删除]      │
│ 夹胸    │ 2026-10-09 · 推日        │ + 补录感悟         │
│         │  45kg×12   第1组          │                    │
└─────────┴──────────────────────────┴───────────────────┘
```

## 3. 数据模型设计

### 3.1 现有训练数据（不动，只读）

现状（来自 flows.json parse-training，15 动作）：



* 每组一条点：measurement=`ppl_push_bench_flat` 等（每动作一个），

  tags=`direction`(push/pull/squat)、`exercise`(中文名)、`set_index`(从 1 起)、`session_id`(=`'s'+消息时间戳`)、`source`

  fields=`weight_kg`, `reps`

* PR 测试：measurement=`ppl_pr_test`，tags 含 `type='pr'`，fields=`weight_kg`, `max_reps`

* 其他：`ppl_duration_min`（训练时长）、`ppl_morning_hr`（晨脉）、`ppl_imagery`（意象打卡）

**关键事实**：`session_id` 由「一条消息」生成 —— 同一训练轮发多条消息会产生多个 session\_id。因此感悟与组的绑定**不能依赖 session\_id 跨消息匹配**，统一用「date + exercise + set\_index」三键锚定（见 §4.3）。

### 3.2 新增 Measurement：`ppl_reflection`

**Tags**：



| tag          | 取值                          | 必填         | 说明                           |
| ------------ | --------------------------- | ---------- | ---------------------------- |
| `id`         | `ref_{YYYYMMDD}_{8位短uuid}`  | ✅          | 唯一标识（复用练枪规则）                 |
| `date`       | `YYYY-MM-DD`                | ✅          | 感悟日期（默认消息当日，可显式指定）           |
| `direction`  | push / pull / squat / other | 组级 / 动作级 ✅ | 冗余便于筛选，由动作映射                 |
| `exercise`   | 动作中文名（如 平板卧推）               | 组级 / 动作级 ✅ | 日级感悟缺省                       |
| `set_index`  | `1..N`                      | 仅组级        | 组级 = 具体第几组；动作级不填（=0 语义）；日级不填 |
| `session_id` | 同消息训练数据的 session            | 可选         | 若消息同时带训练数据则顺带记录，便于直接 join    |
| `source`     | phone / web                 | ✅          | 录入通道                         |

**Fields**：



| field     | 类型     | 说明                      |
| --------- | ------ | ----------------------- |
| `content` | string | 感悟正文（一句话为主，Markdown 兼容） |
| `title`   | string | 可选标题（页面编辑时可填，消息录入默认空）   |
| `tags`    | string | 自由标签，逗号分隔（替代练枪的主题枚举）    |

**Line Protocol 示例**：



```
ppl_reflection,id=ref_20261011_3f9a2b1c,date=2026-10-11,direction=push,exercise=平板卧推,set_index=2,source=phone content="肩胛锁死后推起来更稳，下放节奏慢一点",tags="" 1730000000000000000
```

### 3.3 三级粒度语义



| 粒度    | exercise | set\_index | 典型场景                        |
| ----- | -------- | ---------- | --------------------------- |
| 组级（主） | 平板卧推     | 2          | 「平板卧推 第 2 组 感悟：……」（练完一组马上记） |
| 动作级   | 平板卧推     | 不填         | 「平板卧推 感悟：今天上胸感觉好」（动作练完后总结）  |
| 训练日级  | 不填       | 不填         | 「推日 感悟：整体状态一般，组间拉长到 3 分钟」   |

展示端规则：组级感悟精确挂到组；动作级感悟显示在该动作卡片顶部；日级感悟显示在页面顶部（该日全局）。

## 4. 录入设计（Node-RED 扩展）

### 4.1 消息语法

在**现有 parse-training 之外**新增「感悟解析」逻辑（同一条消息可同时含训练数据 + 感悟，也可纯感悟消息）：



| 语法                          | 绑定                                         |
| --------------------------- | ------------------------------------------ |
| `平板卧推 第2组 感悟：肩胛锁死更稳`        | 组级（date = 当日，exercise = 平板卧推，set\_index=2） |
| `平板卧推 感悟：今天上胸感觉好`           | 动作级（set\_index 不填）                         |
| `推日 感悟：整体状态一般` / `感悟：今天状态差` | 训练日级（日级不指定动作时，可用方向词或省略）                    |
| `平板卧推 47.5kg×8 第1组 感悟：这组最顺` | 训练数据 + 感悟同发，顺带绑 session\_id                |

**识别词**：`感悟` / `心得` / `笔记` / `reflection`。触发后：



* 提取动作（复用现有 15 动作别名表 findExAt）

* 提取组号（`第(\d+)组`）

* 其余文本为 content，写入 `ppl_reflection`

**响应**：纯感悟消息返回 `已记录 1 条感悟（平板卧推·第2组）`；混录返回汇总。

### 4.2 前端页面补录 / 编辑 / 删除

页面右栏 + 弹窗提供：新建（选动作 / 组号 / 日期 / 内容 /tags）、编辑、删除（InfluxDB Delete API，练枪已验证的 delete 模式）。

### 4.3 组级绑定的现实处理（宽松绑定）

练枪的 session\_id 语义是「一次消息」，训练内多条消息 session 不同；且用户可能在录训练数据**之前**就先记了感悟。因此：



* **锚定键 = date + exercise + set\_index**，不依赖 session\_id 跨消息匹配

* 展示时 join 训练数据：按 date+exercise 取当天该动作记录的第 N 组（weight×reps 显示在感悟旁）

* 若当天该组记录尚不存在 → 页面显示「未匹配到组（待训练数据补录后自动匹配）」；训练数据补录后自然对上

* 同一天同一动作多个训练轮（如早 / 晚各练一次）：按记录时间就近匹配，页面可手动改绑

## 5. 展示载体：新增轻量前端（架构）

### 5.1 为什么不能只靠 Grafana

Grafana 只能做面板、跳转、drilldown，做不了「点击动作 → 右侧展开详情 → 侧栏逐组批注」的联动交互。健身项目目前无前端、无后端服务（只有 Node-RED / InfluxDB / Grafana）。

### 5.2 技术方案（2026-10-11 修正：克隆练枪 web 工程骨架，宿主进程跑，不进 docker-compose）

比对练枪实际部署后确认：练枪的 web（FastAPI + React）**不在 docker-compose 里**（compose 只有 influxdb/grafana/nodered 三个容器），而是宿主进程直接跑：`start.bat` 起 uvicorn + vite dev；`start-prod.bat` 先 `npm run build`，再由 FastAPI 用 StaticFiles + SPA fallback 托管 `frontend/dist`，生产单端口访问。健身版完全跟随这一形态。

| 层 | 选型 | 说明 |
| -- | ---- | ---- |
| 编排 | 克隆练枪 `web/` 目录到 training-tracker-docker，宿主进程跑 | docker-compose **不加服务**（现有 influxdb/grafana/nodered 不动）；新增 `start.bat`（dev）/ `start-prod.bat`（prod） |
| 后端 | FastAPI（练枪同款，复制 app/{models,repositories,services} 骨架） | 感悟 CRUD + 训练历史查询 + 统计；InfluxDB token 只留后端；`influx_client.py` 只改 4 个连接常量 |
| 前端 | React + Antd（练枪同款，复制 package.json 与 src 页面组件） | 三段式页面 + 弹窗表单；vite dev `5174`（练枪占用 5173）；生产由 FastAPI 托管 dist |
| 端口 | 后端 `8001`（练枪占 8000）/ 前端 dev `5174` / 生产单端口 `8001` | 避开 3000（Grafana）/ 1880（Node-RED）/ 8086（InfluxDB）/ 练枪 8000、5173 |

**备选（不推荐）**：

* 无后端、前端直连 InfluxDB API：需开 CORS 且 token 暴露（读写全权限，不安全）

* 用 Node-RED HTTP 节点当 API：少一个服务，但复杂查询 / 分页 / 编辑体验差

### 5.3 后端 API 清单



| 方法     | 路径                                                                           | 说明                                                                          |
| ------ | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| GET    | `/api/reflections?date=&exercise=&direction=&set_index=&tag=&limit=&offset=` | 感悟列表（筛选）                                                                    |
| POST   | `/api/reflections`                                                           | 新建感悟                                                                        |
| GET    | `/api/reflections/{id}`                                                      | 单条详情                                                                        |
| PUT    | `/api/reflections/{id}`                                                      | 更新（删除 + 重写，保留 id，练枪模式）                                                      |
| DELETE | `/api/reflections/{id}`                                                      | 删除                                                                          |
| GET    | `/api/training/exercise/{exercise}`                                          | 该动作历史训练（按 session 分组：date/direction/session\_id + 每组 weight×reps）—— 前端中栏数据源 |
| GET    | `/api/reflections/stats`                                                     | 统计（总数 / 今日 / 连续天数 / 覆盖动作数）                                                  |

### 5.4 前端页面结构（对照 §2）



* 左栏：动作列表（推 / 拉 / 蹲分组，数据源 = 15 动作清单）

* 中栏：`/api/training/exercise/{exercise}` + `/api/reflections?exercise=` 合并渲染

* 右栏：选中组 → 对应组级感悟；选中动作卡片 → 动作级感悟；顶部 → 日级感悟

* 弹窗：新建 / 编辑表单（练枪 ReflectionForm 改造）

* 列表标记：有感悟的组显示 💬

## 6. Markdown 同步（保留练枪模式）



* 目录：`docs/记录/训练感悟/YYYY-MM-DD.md`（练枪为 游戏感悟，健身独立目录）

* 单条格式（组级示例）：



```
### 平板卧推 · 第2组（47.5kg×8）—— 肩胛锁死后推起来更稳
**方向**: 推日 | **动作**: 平板卧推 | **组**: 2 | **录入**: 消息
**标签**: 发力感
肩胛锁死后推起来更稳，下放节奏慢一点。
<!-- reflection_id: ref_20261011_3f9a2b1c -->
```



* 双向：写入时增量同步（练枪 sync\_reflection\_to\_markdown 逻辑）；读取时从 md 导入（import\_all\_from\_markdown）

* 动作级：`### 平板卧推 —— 今天上胸感觉好`；日级：`### 训练日随笔 —— ……`
