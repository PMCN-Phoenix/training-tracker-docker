## 2. InfluxDB / Flux

1. **Flux 没有 `!=~`**：取反要写 `not r._field =~ /regex/`。
2. **同一批写入的点时间戳相同**（都取 `Date.now()` 或 `?time` 参数）：查询时不能用 `_time` 区分组 → 写入必须带 `session_id` + `set_index` 标签；面板查询 `pivot` 的 rowKey 必须含 `["_time","session_id","set_index"]`。
3. **Flux 字段是独立表**：`weight_kg` 和 `reps` 各占一行，算容量（重量×次数）前必须先 `pivot` 到同一行，否则 `map` 里取不到另一个字段。
4. **`aggregateWindow` sum 后 `_time` 可能丢失** → 用 `aggregateWindow(every: 1d, fn: sum, createEmpty: false)` 重建时间。
5. **删除数据用 API**：`POST /api/v2/delete?org=…&bucket=…`，body `{"start","stop","predicate"}`；`start/stop` 必须覆盖数据时间范围，`predicate` 如 `source="verify"` 或 `session_id="s…"`。
6. **验证测试数据会污染正式库**：所有 curl 录入测试一律带 `?source=verify`（自定义来源），验收后统一删除；不要用默认 `phone`。**本次收尾时就犯了此错**（一条不带标记的测试写进了 phone，随后按 session_id 删除恢复，见 §5）。
7. **持久化对比只看业务列**：重启前后查询的 `_start/_stop` 是查询时刻，必然不同；对比只取 `_measurement`+`_value`。

### 7.2 新坑（本次新增，下次先看这里）
1. **Python 写 flows 正则双重转义**：Python 字符串里写 `\\s` 会落盘成字面 `\s` → 正则失效。教训：改 flows.json 中的正则时按 JSON 规则写，改完必须 `ConvertFrom-Json` 校验（本项曾导致从备份恢复重写）。
2. **PR 的重量必须同时写为 tag**：Flux 的 `group()` 只能按 tag/列分组，字段（`weight_kg`）无法参与 → PR 面板画不出分档线。教训：需要按某值分组的量，写库时同时做成 tag。
3. **Flux 多来源帧要 `group(columns: [])` 归并**：不同 source/session 的分组会拆成多帧，`movingAverage` 断帧无效 → 算移动平均前先归并。
4. **InfluxDB delete API 谓词不支持 `or`**：多条件删除要逐条发请求。
5. **PowerShell `$pid` 是只读保留变量**：循环变量改用 `$panelId`，否则报错。
6. **大段含 `$` 的 PowerShell 会被传输层拦截**：写脚本/长命令改用 node_repl 或 Python。
7. **Grafana 10.4 面板 DOM 选择器**：`.panel-container` 可能匹配不到，用 `[data-panelid]` 或 `.react-grid-item` 定位截图。
8. **InfluxDB 查询 CSV 列偏移随查询形态变化**：`count()` 直查时 `_value` 在第 6 列（index 5）；`distinct |> group() |> count()` 后表头只剩 `_value`，在第 4 列（index 3）。解析前先打印原始输出看表头，别凭经验取列。
9. **桌面 .bat 中文标题乱码**：系统默认 GBK 写入的中文 bat 用 UTF-8 解码就是乱码；要显示中文标题必须「UTF-8 无 BOM + chcp 65001」或「ANSI/GBK」二选一，生成后用字节检查确认（本次 `一键打开训练系统.bat` 的 title 行乱码，已重写）。
10. **时长解析器只认「小时/分钟」**：秒表格式 `01:19:31.40` 不会被解析（正则要数字+单位），须手动换算成分钟录入（本例 ≈79.5 → 80 分钟）；如想直接支持 HH:MM:SS，需改 flows.json 增加正则。
11. **杠铃弯举从忽略清单转正**（2026-08-10）：原设计「不建指标」里的杠铃弯举用户开始真实记录 → 在 flows.json 的 EX 数组加 `ppl_pull_barbell_curl`（拉日，别名 `杠铃弯举`/`弯举`）并重启 nodered 即生效；动作面板按 direction 动态分组，拉日容量/最重面板自动变 5 条线，无需改面板 JSON。另：手工加总点数易错（曾把 demo 动作行 204 误加为 200，文档合计差 4）→ 数据状态表一律查库取数。

### 8.2 新坑与经验（下次先看这里）
1. **秒表分段格式只取最后一个 total**：`01 +01:31:34.94 01:31:34.94 / 02 +18:14.35 01:49:49.29` 中前两个是分段（split），只有最后的 `01:49:49.29` 是训练总时长（≈110 分钟）；中间的 `18:14` 不要误当总时长。
2. **口语格式必须先转写**：用户原文「40kg最多17个」「3*12*30」解析器不识别 —— 只认「重量×次数」（`×/x/*`）。转写规则：`40kg最多17个`→`40kg×17`；`3*15*50kg`（3 组×15 次×50kg）→ 拆成 3 条 `50kg×15`。
3. **PR 与容量组必须分两条消息**：以 `PR`/`测试` 开头后整条消息全部按 PR 记录；同一天的日常容量组另发一条不带 PR 的消息（本次 PR 一条 + 提踵容量一条 + 时长一条）。
4. **幂等写入**：写真实数据前先查「当日 + source + 相关 measurement」的计数，已存在则跳过，防止重复录入（本次复核脚本检测到前一轮会话已写入即跳过）。
5. **PowerShell 内联 `node -e` 极易被引号/中文破坏**：本次两次 `node -e` 均失败（引号被吞）；改为 `Set-Content -Encoding UTF8` 写临时 .js 再 `node file.js` 即通过。
6. **查库计数口径**：每个点有 2 个字段（weight_kg + reps/max_reps），「档/组数」= 字段行数 ÷ 2；写数据状态表一律重新查库，别手工推算。
7. **补录/并入历史轮次用 `?time=`**：session_id = `s` + 毫秒时间戳；补录历史 PR 时带 `?time=<原session时间>` 即可并入原轮次（2026-08-12 补录站姿推举 PR 10kg×14 → 并入 08-08 推日轮次 s1786187923422），PR 面板按轮次推进不乱。
