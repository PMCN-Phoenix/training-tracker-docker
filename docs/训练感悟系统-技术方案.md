# 训练感悟系统 - 技术方案

> 项目：training-tracker-docker（推拉蹲训练记录系统）
> 状态：**v1.0 定稿（2026-10-11）**，技术栈经多轮比对与讨论，用户逐项确认，进入开发（M1→M5）
> 关联文档：产品设计文档 v1.0（交互/数据模型/决策记录，本方案承接其架构）；练枪 aim-tracker-docker（复用底稿，已实读 main.py / influx_client.py / frontend package.json / flows.json）
> 决策口径：用户「按推荐来」确认：① react-query 管数据 + zustand 存 UI 状态；② 路由 URL 化（可分享/刷新保持）；③ 图表维持手写 SVG（不引 echarts）

---

## 1. 方案定位

给推拉蹲训练记录系统新增「训练感悟系统」Web 应用：消息录入感悟 → 落 InfluxDB → FastAPI 提供查询/CRUD → React 增强三栏页面展示（点击动作 → 历史组×重量 → 侧栏逐组感悟）→ 按日 Markdown 双向同步。

**核心原则**：
1. **克隆练枪 web 工程骨架**（FastAPI + React），重合度最大化，只改必要处
2. **宿主进程跑，不进 docker-compose**（练枪实测形态：compose 只有 influxdb/grafana/nodered，web 是 start.bat 起的宿主进程）
3. **不动现有训练数据模型与容器**（ppl_\* measurement 原样保留，Node-RED 容器只更新 flows.json）

## 2. 架构总览

```
┌──────────────────────── 录入层 ────────────────────────┐
│ 手机/网页 POST /add-training（自然语言消息）            │
│ Node-RED parse-training（扩展：感悟解析）               │
└──────────────┬────────────────────────────────────────┘
               ▼ Line Protocol
┌──────────────────────── 存储层 ────────────────────────┐
│ InfluxDB 2.x (8086, org=training-org, bucket=training) │
│ 新增 ppl_reflection + 既有 ppl_* (只读)                │
└──────────────┬────────────────────────────────────────┘
               ▼ urllib 直连（后端中转，不暴露 token）
┌──────────────────────── 服务层 ────────────────────────┐
│ FastAPI（宿主进程 127.0.0.1:8001）                     │
│ 感悟 CRUD / 训练历史 / PR 查询 / day 全貌 / stats       │
│ Markdown 双向同步（docs/记录/训练感悟/YYYY-MM-DD.md）   │
└──────────────┬────────────────────────────────────────┘
               ▼ REST JSON
┌──────────────────────── 展示层 ────────────────────────┐
│ React 19 + Vite 8 + antd 6（dev 5174 / 生产由 FastAPI  │
│ 托管 dist，单端口 8001）                                │
│ 增强三栏 + 双模式 + PR 体系（SVG 图表）                │
└────────────────────────────────────────────────────────┘
```

数据流主链路：**消息录入（组间/练后即时）→ ppl_reflection → 页面按 date+exercise+set_index 锚定 join 训练数据 → 侧栏逐组展示**。

## 3. 技术选型（定案）

| 层 | 选型 | 理由 | 练枪对照（已实读） |
|---|---|---|---|
| 前端框架 | **Vite 8 + React 19 + antd 6** | 练枪同款，页面/组件可整文件移植；antd 弹窗/表单/抽屉开箱即用 | `frontend/package.json` 原样复制依赖 |
| 前端数据 | **@tanstack/react-query 5**（数据）+ **zustand 5**（仅 UI 状态） | 感悟/训练/PR 是查询型数据，react-query 管缓存/重取；UI 状态（选中组/模式/筛选）量小，zustand 够用 | 练枪同款依赖，本项目按「react-query 为主、zustand 只存 UI」使用 |
| 路由 | **react-router-dom 7 + URL 化** | `/?mode=ex&exercise=平板卧推` / `/?mode=day&date=2026-10-11`，可分享、刷新保持、Grafana/PR 深链可回 | 练枪已依赖；本项目首次启用 URL 路由 |
| 图表 | **手写 SVG**（转 React 组件） | demo 版 SVG 已通过多重验证（迷你图双线/PR 多系列曲线/联动），零依赖、视觉可控；echarts 保留依赖但本场景不用 | demo 代码直接迁移为组件 |
| 后端框架 | **FastAPI** + `ApiResponse` 统一响应 + CORS + SPA fallback | 练枪 main.py 整文件复制改造 | `aim-tracker-docker/web/backend/app/main.py` |
| Influx 客户端 | **urllib 直连 + csv 解析**（无第三方库） | 练枪 influx_client.py 只改 4 个连接常量；后端中转避免 token 暴露 | `repositories/influx_client.py`（8087→8086、aim-org→training-org、aim→training、token 换） |
| 感悟仓储 | CRUD（更新=删除+重写保留 id）+ escape + stats | 练枪 game_reflection_repo 移植 | 改 measurement/tags → `ppl_reflection_repo.py` |
| Markdown 同步 | 按日双向同步（练枪模式） | 人类可读、备份、可导入导出 | `services/game_reflection_markdown.py` 改目录/格式 |
| 录入扩展 | Node-RED function 节点内新增感悟解析 | 与训练解析同一消息通道，复用 findExAt/动作别名表 | 改 `nodered_data/flows.json` parse-training |
| 部署 | **宿主进程**，不进 compose | 练枪实测形态；compose 不动，新增 start.bat / start-prod.bat | `start.bat`/`start-prod.bat` 改路径端口 |

|---|---|

| 5174 | vite dev 前端 |

## 4. 数据模型落地

### 4.1 新增 measurement：`ppl_reflection`

Tags：`id`(ref_{YYYYMMDD}_{8hex}) / `date` / `direction` / `exercise` / `set_index`(组级) / `session_id`(混录顺带) / `source`
Fields：`content`(string) / `title`(可选) / `tags`(逗号分隔)

三级粒度：组级=exercise+set_index；动作级=exercise 无 set_index；日级=无 exercise。

### 4.2 绑定策略（宽松绑定，v1.0 只自动）

- **锚定键 = date + exercise + set_index**（session_id 跨消息不一致，不可依赖）
- 展示时按 date+exercise 取当天该动作第 N 组 weight×reps 并排展示
- 组尚不存在 → 「待匹配」卡片，训练数据补录后自动对上
- 同一天同动作多轮：按记录时间就近匹配；**手动改绑暂缓**（错配再考虑）

### 4.3 只读的现有数据（供查询）

- 训练组：每动作一 measurement（ppl_push_bench_flat 等 15 个），tags=direction/exercise/set_index/session_id/source，fields=weight_kg/reps
- PR 测试：`ppl_pr_test`（tags.type=pr，fields.weight_kg/max_reps）；「每次测试」= 同日同消息一组点，按日期升序编号
- 晨脉 `ppl_morning_hr` / 意象 `ppl_imagery` / 时长 `ppl_duration_min`（按日模式整合展示）

## 5. 后端 API（FastAPI，127.0.0.1:8001）

统一 `ApiResponse{code,message,data}`。完整清单：

| 方法 | 路径 | 说明 | 数据源 |
|---|---|---|---|
| GET | `/api/reflections?date=&exercise=&direction=&set_index=&tag=&limit=&offset=` | 感悟列表（筛选） | ppl_reflection |
| POST | `/api/reflections` | 新建 | ppl_reflection |
| GET | `/api/reflections/{id}` | 单条 | ppl_reflection |
| PUT | `/api/reflections/{id}` | 更新（删除+重写保留 id） | ppl_reflection |
| DELETE | `/api/reflections/{id}` | 删除 | ppl_reflection |
| GET | `/api/reflections/stats` | 总数/今日/连续天数/覆盖动作 | ppl_reflection |
| GET | `/api/training/exercise/{exercise}` | 该动作历史（按 session 分组：date/direction/session_id+每组 w×r） | 15 训练 measurement |
| GET | `/api/pr/tests` | 全动作 PR 测试（按动作+日期分组） | ppl_pr_test |
| GET | `/api/day/{date}` | 当天全貌（训练组行+日级感悟+晨脉+意象） | 多 measurement 合并 |

**新增模块**：`training_queries.py`（session 分组查询）、`pr_queries.py`（PR 分组/编号）、`ppl_reflection_repo.py`（移植）、`ppl_reflection_markdown.py`（移植）。
**复用**：`influx_client.py`（只改 4 常量）、`main.py`（删练枪接口，留 ApiResponse/CORS/SPA fallback）。

## 8. 关键实现细节

1. **SVG 迁移**：demo（`docs/感悟系统demo/训练感悟系统-v1.0完整demo.html`）的迷你图双线 / PR 多系列曲线 / 联动逻辑已通过五级验证，直接转 React 组件（props 接 API 数据），视觉与 demo 一致
2. **组级锚定 join**：前端拿 `/api/training/exercise/{ex}` + `/api/reflections?exercise=` 后按 date+set_index 合并；待匹配 = 有感悟无对应组
3. **PR 编号**：按测试日期升序第 1/2/3… 次，hover 显示日期；两两对比下拉 value=索引+1（demo 已验证的映射，避免重蹈 `no` 字段 bug）
4. **宽松绑定查询**：`/api/day/{date}` 一次返回当天全部（训练+日级感悟+晨脉+意象），按日模式单请求
5. **消息响应**：纯感悟消息返回「已记录 1 条感悟（平板卧推·第2组）」；混录返回汇总
