### 3.2 Node-RED 解析规则（flows.json，智能解析层）

HTTP 节点：`POST /add-training`，接收 `text/plain` 或 JSON 的 `text` 字段。

当前解析器为「推拉蹲动作 + 组序列」语法（2026-08-07 起替代旧的 5 条指标正则，旧数据/旧仪表盘不受影响）：

**① 语法格式**

```
推日 平板卧推 60kg×12 70kg×10 80kg×8 上斜卧推 50kg×12 60kg×10
```

**② 解析规则**
- 动作名后面的「重量×次数」序列自动归属该动作，遇到下一个动作名截止（例：平板卧推 3 组、上斜卧推 2 组）；
- 分隔符支持 `×` / `x` / `*`；重量可带 `kg`/`公斤`/`千克` 也可省略；支持小数重量（如 `62.5kg×8`）；
- 每组写一条数据点，组间用 `set_index` 标签区分（从 1 开始）；
- 无组数跟随的动作名会被忽略（如只写"平板卧推"没有组明细）；
- 不建指标的写法会被忽略：绳索下压/侧平举、站姿提踵；其余可识别动作照常记录；
- 全部无法识别 → 返回 `400 {"ok":false,"message":"未能识别训练数据","detail":"原文"}`；部分识别 → `200 {"ok":true,"message":"已记录 N 个动作 M 组"}`；
- 训练时长（可与动作同一条消息）：关键字 `训练时长/训练时间/训练/练了/锻炼` + 数字 + `小时`/`分钟`（别名 `h`/`hr`/`hrs`、`min`/`mins`/`分`，可混合，如 `训练 1.5小时 20分钟`），自动折算分钟写入 `ppl_duration_min`；方向取消息内最近的方向词（推日/拉日/蹲日），否则取动作方向，再否则 `other`；
- PR 检验（每 4 个周期 ≈ 12 练后测一次）：整条消息以 `PR` 或 `测试` 开头 → 本条所有动作按 PR 记录（每重量档位一条点，fields=`weight_kg`+`max_reps`）到 `ppl_pr_test`；PR 与日常组请分两条消息发（同一天可以两条）；
- 晨脉（静息心率，每天一次，可与动作/训练时长同一条消息）：关键字 `晨脉`/`静息心率`/`早起心率`/`晨起心率`/`早晨心率` + 数字（可带 `次`/`bpm`，支持小数，如 `晨脉 62`、`静息心率 58.5`）→ 写入 `ppl_morning_hr`，fields=`bpm`；纯晨脉消息返回 `已记录 1 条晨脉`；
- 意象训练打卡（动作意象实验，每周 3~5 天，完成即发，可与动作/晨脉同一条消息）：消息含关键字 `意象`/`意念`/`心理预演`/`imagery` → 写入 `ppl_imagery`，fields=`done`=1；纯意象消息返回 `已记录 意象训练`；
- 写入目标：org=`training-org`，bucket=`training`，URL=`http://influxdb:8086`（容器内网名）。

**④ 写入格式（每组一条点）**
- `measurement` = 指标名（上表"指标名"列）；
- `fields`：`weight_kg`（重量 kg）、`reps`（次数）；
- `tags`：`direction`（push/pull/squat）、`exercise`（显示名）、`set_index`（组号）、`session_id`（每次录入生成一个，形如 `s+时间戳`）、`source`（来源）；
- 时间戳：默认服务器当前时刻，可用 `?time=2026-07-20T10:00:00+08:00` 指定（写演示数据用）；`?source=demo` 可指定来源（默认 `phone`）。
- 时长点：measurement=`ppl_duration_min`，fields=`minutes`，tags=`direction`/`session_id`/`source`；
- PR 点：measurement=`ppl_pr_test`，fields=`weight_kg`/`max_reps`，tags=`direction`/`exercise`/`set_index`/`session_id`/`source`/`type=pr`，且 `weight_kg` 同时写为 tag（Flux 按档位分组画线需要）；
- 晨脉点：measurement=`ppl_morning_hr`，fields=`bpm`（次/分），tags=`session_id`/`source`；时间戳=录入时刻（实测方法：晨醒后躺 3~5 分钟再测，手动桡动脉数满 60 秒或 30 秒×2，见处方文档「每日维护清单」一节）；

> 旧版 5 条指标正则（跑步距离/时长、深蹲重量/组数、引体向上）已被替代：旧数据仍在库里、旧"训练监控"仪表盘照常显示；旧解析规则备份在 `nodered_data\flows.json.bak-ppl-20260807`。

## 4. 操作方法

### 4.1 启动 / 停止 / 重启 / 状态

```powershell
cd D:\11.project\iwen-codex\codex-list\training-tracker-docker

docker compose up -d            # 首次构建并启动全部容器
docker compose ps               # 查看状态（3 个都 Up 为正常）

### 4.2 录入数据（三种方式）

**① 网页直测（最直观）**
浏览器打开 http://localhost:1880 ，左上角"部署"旁有个调试侧栏；更简单的方式是直接在浏览器地址栏的录入测试工具（Node-RED 编辑器 → 右侧调试 → 用 HTTP 节点测试需另配；推荐直接用法 ②/③）。

**② 命令行（Windows，必须用 curl.exe）**

```powershell
curl.exe -X POST http://localhost:1880/add-training ^

  --data-binary "推日 平板卧推 60kg×12 70kg×10 80kg×8 上斜卧推 50kg×12 60kg×10"
```

返回：`{"ok":true,"message":"已记录 2 个动作 5 组"}`

curl.exe -X POST "http://localhost:1880/add-training" -H "Content-Type: text/plain; charset=utf-8" --data-binary "PR 推日 平板卧推 70kg×10 80kg×6"
```
返回：`{"ok":true,"message":"已记录 1 个动作(PR) 2 档"}`"
```

**晨脉（静息心率，每天一次，手动桡动脉计数）**：
```powershell
curl.exe -X POST http://localhost:1880/add-training -H "Content-Type: text/plain; charset=utf-8" --data-binary "晨脉 62"
```
返回：`{"ok":true,"message":"已记录 1 条晨脉"}`（可与动作/训练时长同一条消息，如 `推日 平板卧推 60kg×12 晨脉 61` → `已记录 1 个动作 1 组，1 条晨脉`）

**意象训练打卡（动作意象实验，每天一次，完成即发）**：
```powershell

```
返回：`{"ok":true,"message":"已记录 意象训练"}`（可与晨脉同一条消息，如 `晨脉 62 意象 完成` → `已记录 1 条晨脉，意象训练`）

**感悟（组级 / 动作级 / 日级，可与训练组同一条消息）**：
```powershell
# 组级：动作 + 第N组 + 感悟：内容（绑定到该动作第 N 组）
curl.exe -X POST http://localhost:1880/add-training -H "Content-Type: text/plain; charset=utf-8" --data-binary "平板卧推 47.5kg×8 第1组 感悟：起桥稳住后推起更顺。"
# 动作级：动作 + 感悟：内容（无组号 → 绑定到该动作）
curl.exe -X POST http://localhost:1880/add-training -H "Content-Type: text/plain; charset=utf-8" --data-binary "平板卧推 感悟：肩胛锁定做满了全程。"
# 日级：训练日随笔 + 感悟：内容（无动作 → 当天随笔）
curl.exe -X POST http://localhost:1880/add-training -H "Content-Type: text/plain; charset=utf-8" --data-binary "训练日随笔 感悟：今天状态一般，晨脉偏高，减了一档。"
```
识别词：`感悟`/`心得`/`笔记`/`reflection`；内容=识别词后文（可带冒号/逗号/箭头分隔）。组号规则：识别词**前**最近一个"第N组"；无动作时按识别词前最近动作绑定；既无动作也无"推日/拉日/蹲日"→ 方向 other。
> ⚠️ 消息录入（Node-RED 直写 InfluxDB）**不会自动触发** Markdown 同步；需要生成/刷新 `docs\记录\训练感悟\` 时执行：
> `curl.exe -X POST http://127.0.0.1:8001/api/reflections/markdown-sync`
> （页面录入 / 编辑 / 删除会自动同步，无需手动跑）

> ⚠️ 不要用 PowerShell 的 `Invoke-RestMethod` 发中文，会乱码导致识别失败；curl.exe 已验证可用。

**③ 手机（同局域网）**

## 6. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 返回 400 "未能识别训练数据" | 动作不在 12 个清单内 / 缺组序列 / 中文乱码 | 检查写法（见 3.2 动作清单）；改用 curl.exe；重启 Node-RED 后重试 |
| PowerShell 发中文变乱码 | `Invoke-RestMethod` 编码问题 | 一律用 `curl.exe --data-binary` |
| Grafana 面板空白 | 数据源连接断 / 时间范围无数据 | 等 10s 自动刷新；切时间范围；`docker compose restart grafana` |
| 容器全部 Exited | Docker/WSL2 未启动 | 打开 Docker Desktop 等引擎就绪再 `docker compose up -d` |
| 端口被占用 | 3000/8086/1880 被其他程序占用 | 关闭占用程序，或改 compose 端口映射 |
| Grafana 登录失败 | 之前已改过密码 | 用你设置的新密码；忘记可重置（需要时找我） |
| 改了 flows.json 不生效 | 未重启 / JSON 语法错误 | `docker compose restart nodered`；用 `node -e "JSON.parse(require('fs').readFileSync('nodered_data/flows.json','utf8'))"` 检查语法 |
| 手机连不上 | 不同网段 / 防火墙 | 电脑手机同一 Wi-Fi；放行 1880；URL 用局域网 IP |
